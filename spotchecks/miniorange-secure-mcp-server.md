# miniorange-secure-mcp-server spot-check

Version checked: 1.5.3. Verdict: Mostly holds: auth, capability checks, scoping, secrets and logging are as described, and no feature sits behind a licence check. But SAFE-CONFIRM and STD-TRANSPORT are scored too high and HOST-LOCAL too low.

## Other findings
- `allow_plugin_routes()` matches route substrings: any route containing `/mosmcp/v1/mcp`, `/token` or `/register` clears a security plugin's REST-auth block (`includes/common/hooks/class-hooks.php:245`). Core routes with free-form path parameters (e.g. templates) could carry that substring, which would bypass a third-party "REST requires login" lockdown. Core permission callbacks still apply, so the impact is limited. Not verified by running it.
- Direct connections get a model-directed "deprecated, will stop working, switch to miniOrange Gateway" instruction in `initialize` (`includes/common/services/mcp/class-mcp-server.php:435`) and in tool results (`:245`). The review notes this. Worth repeating because it is prompt-level steering towards the vendor's service.
- The review's SEC-SECRETS evidence `includes/common/repositories/class-store.php:21` is a docblock. The hashing itself is at `includes/common/services/oauth/class-tokens.php:86`.
